# Android-приложение «Sharpwise»

Папка содержит Android-оболочку для того же учебника из соседнего `wwwroot`. В APK входят уроки, архивы проектов, редактор и обе среды выполнения. Приложение открывает содержимое во встроенном Android System WebView. Для сетевых сокетов локального сервера используется разрешение INTERNET. Сервер слушает только 127.0.0.1. Внешние ссылки открывает выбранный на телефоне браузер, а проекты ZIP сохраняются через системный выбор файла.

Для запуска примеров C# 15 на .NET 11 нужен Android System WebView версии 137 или новее. Версию компонента можно открыть в настройках приложений Android.

## Сборка на Windows

Нужны PowerShell, JDK 17–25, Python 3 и команды curl.exe и tar.exe. В папке подписи хранится `sharpwise-signing.p12` с ключом `sharpwise`. Передай пароль через переменную окружения `CSHARPBOOK_ANDROID_PASS` либо используй `password.dpapi` в той же папке под соответствующей учётной записью Windows. Скрипт сверяет сертификат ключа и готового APK с `stable-cert.sha256`. Путь к папке передаётся через `-SigningDir`.

Стабильный APK из корня проекта собирается так.

```powershell
pwsh -File ./android/Build-Apk.ps1 -SigningDir C:\Sharpwise\signing
```

Путь к JDK можно передать через `-JavaHome`, к итоговому APK — через `-OutputApk`. Первая сборка скачивает Gradle 9.1.0 и Android SDK 36. Gradle получает NanoHTTPD, Google Play services Auth и их зависимости из Google Maven и Maven Central. В последующих сборках используются локальные копии. Перед созданием пакета подготовь итоговые `course.json`, `sw.js` и каталоги `runtime` и `projects` в `wwwroot`.

Прямой вход в Google Диск и Яндекс Диск включён в обычной и тестовой сборках. Gradle упаковывает `../cloud-sync.defaults.json` в `assets/cloud-sync.json`. Чтобы использовать собственную регистрацию провайдера, заполни копию `cloud-sync.example.json` и передай путь через `-CloudConfig`. Обычная сборка также поддерживает локальный файл `android/cloud-sync.json`.

Версия 0.5.1 для Android подписана новым постоянным ключом. Перед удалением 0.5.0 синхронизируй прогресс и проверь резервную копию. Затем установи APK 0.5.1 вручную и восстанови прогресс. Следующие стабильные версии и официальные беты используют один пакет и один ключ.

Для беты укажи номер и Android-код версии. Код каждой распространяемой сборки должен быть выше предыдущего в этом пакете. Зарезервируй больший код для будущего стабильного выпуска в `AndroidManifest.xml`. В выпуске 0.3.6 у первой беты код 12, у стабильной код 13.

```powershell
pwsh -File ./android/Build-Apk.ps1 -BetaNumber 1 -BetaVersionCode 12 -SigningDir C:\Sharpwise\signing
```

Короткий вариант `-Preview` собирает первую бету с кодом на единицу ниже стабильной. Gradle создаёт неподписанные APK через `assemblePreview` и `assembleRelease`. Скрипт подписывает оба варианта одним ключом. Параметры `-CloudConfig` и `-OutputApk` действуют для обоих вариантов.

Для распространения одобренных бет используется один предварительный релиз GitHub с тегом `beta`. Прикрепи подписанный APK с именем вида `Sharpwise-0.5.2_b.2-Android.apk`. Если в релизе несколько бет, Sharpwise рассматривает последнюю по номеру версии. Галочка «Получать бета-версии» включает эту проверку в дополнение к проверке стабильного релиза.

Для установки поверх предыдущей сборки подпиши APK ключом стабильного выпуска и увеличь Android `versionCode`. Код следующей стабильной сборки должен быть выше кода всех выпущенных бет, чтобы пользователи могли вернуться в стабильный канал с сохранением прогресса.
